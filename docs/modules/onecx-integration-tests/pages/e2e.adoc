= End-to-End Test Execution and Artifacts

This page explains how to configure and trigger E2E test execution, what platform metadata the runner exports for use inside tests, and where results are written after the E2E container exits. E2E execution is entirely configuration-driven through `platform.json`; no additional CLI arguments are required once the E2E container image is available.

== Overview

E2E execution is configuration-driven.

When `platformConfig.container.e2e` contains entries, the runner starts the platform, waits for health checks, executes E2E containers sequentially in array order, collects all results, and then shuts down all resources.

Only one E2E container runs at a time.

If the process receives `SIGINT` or `SIGTERM`, the runner finishes the current container, skips remaining E2E containers, cleans up the platform, and writes the received signal to the `interruptedBy` field in `summary.json`.

== Prerequisites

Before running E2E:

* Install Node.js, npm, and Docker
* Provide a valid `platform.json`
* Configure at least one entry in `platformConfig.container.e2e` with `image` and `networkAlias`
* Ensure the E2E image can access Shell UI and Keycloak over the Docker network
* Set `ignoreHTTPSErrors: true` in the Playwright config used by the E2E image (see xref:e2e.adoc#_tls_and_self_signed_certificates[TLS and Self-Signed Certificates])

Minimal E2E configuration:

[source,json]
----
{
	"platformConfig": {
		"container": {
			"e2e": [
				{
					"image": "ghcr.io/onecx/onecx-shell-e2e:latest",
					"networkAlias": "shell-e2e"
				}
			]
		}
	}
}
----

== Running E2E Tests

Run E2E through the integration test runner:

[source,bash]
----
npm run it:run -- --verbose --capture-logs
----

Use dry-run to validate setup without starting containers:

[source,bash]
----
npm run it:run -- --dry-run
----

== TLS and Self-Signed Certificates

Shell, Keycloak, and every UI/MFE container serve HTTPS on `8443` using a self-signed, test-only certificate so the shell runs as a secure browser context (required for `keycloak-js` PKCE login). The same certificate is reused across all UI container hostnames, so its CN/SAN will not match most of them.

The caller-owned Playwright config in `integration/e2e/playwright.config.ts` must set:

[source,typescript]
----
use: {
  ignoreHTTPSErrors: true,
}
----

Trusting the CA instead of setting this flag does not work: because the certificate is shared across hostnames, Chromium's hostname verification still fails for every container other than the one the certificate's CN happens to match.

== Platform Metadata for E2E

During startup, the runtime exports platform metadata to:

`integration-tests/artifacts/<run-id>/e2e/platform-info.json`

The file contains:

* Docker network details
* Internal URLs for container-to-container access
* External URLs for host-side debugging
* Container runtime metadata

Use this metadata inside E2E tests to resolve runtime endpoints consistently.

== Artifacts

E2E-relevant outputs are written under:

`integration-tests/artifacts/<run-id>/`

Key paths:

* `summary.json`
* `e2e/platform-info.json`
* `e2e/e2e-executions.json`
* `e2e-results/`
* `logs/runner-output.log`
* `logs/containers.log` when `--capture-logs` is enabled

Use `summary.json` as the first source for pass/fail state and aggregate E2E result counters.

The summary uses `e2eExecutions` for the ordered per-container records and `e2eAggregate` for total, succeeded, failed, and final status counts. The same report is also written to `e2e/e2e-executions.json`.

The former standalone `start-e2e` entry point and its `--config`/`CONFIG_PATH` options are removed. Configure E2E containers in `platformConfig.container.e2e` and run them through the integration test runner.

== Troubleshooting

Common checks:

* Verify `platformConfig.container.e2e` contains at least one entry
* Confirm the E2E image is available in your registry
* Check `e2e/platform-info.json` for expected URLs
* Review `logs/containers.log` for startup and health-check failures
* Increase `timeoutMs` for slow CI environments
